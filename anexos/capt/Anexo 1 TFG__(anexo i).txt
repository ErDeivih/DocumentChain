1 INTRODUCCIÓN
En este documento se pretende estudiar la planificación temporal del proyecto
durante la realización de este.
Durante este proceso, se identificarán las diferentes tareas a desarrollar, se les
asignarán distintos tiempos y recursos que marcarán un tiempo de duración para esas
tareas, y, finalmente, se planificará una secuencia de ejecución de estas tareas tratando
de reducir el tiempo total de desarrollo al mínimo posible.
Para ello, se realizará una estimación temporal utilizando un diagrama de Gantt,
teniendo en cuenta que para el desarrollo del proyecto se ha seguido el marco de
desarrollo del Proceso Unificado. Con este diagrama se presentan de una forma visual
mediante gráficas la estimación de tiempo de cada tarea y del desarrollo del proceso en
su conjunto.
Finalmente, se desarrollará un marco de trabajo liderado por el uso de la
metodología del Proceso Unificado y un desarrollo software guiado por la utilización de
casos de uso, con lo que se podrá desarrollar el proyecto de manera iterativa e
incremental, dividiendo el tiempo de desarrollo en distintas interacciones, proponiendo
mejoras para el proyecto entre las mismas. Esto mismo se puede observar en la
ilustración expuesta a continuación, donde podemos ver el desarrollo de un proyecto
dividido en fases, y dentro de estas fases las interacciones:

2 ESTIMACIÓN TEMPORAL
En primer lugar, se comenzará con una estimación del tiempo que se destinará para
cada una de las fases según los distintos casos de uso a desarrollar, los actores
implicados y otros factores que afectan directamente al tiempo de desarrollo de un
proyecto. Los casos de uso y los actores pueden ser consultados en el siguiente anexo:
“Anexo II: Especificación de requisitos software”.
Para ello, se usará la herramienta EZEstimate una vez se hayan concretado los
pesos de los distintos parámetros (puntos de caso de uso) para sacar una estimación
de tiempo total del desarrollo.

T1 Sistemas Distribuidos: Se le ha asignado el valor de 1 ya que, aunque la
aplicación pueda trabajar en varios dispositivos a la vez, solo se dispone de
1 robot y 1 servidor, por lo que ese servidor se encargará de todas las
peticiones.
T2 Rendimiento: Se le ha asignado el valor de 3 porque se necesita un
rendimiento no muy alto pero lo suficiente como para proporcionar un buen
servicio a los clientes y una buena comunicación con el robot.
T3 Eficiencia del usuario final: Se le ha asignado el valor de 2 ya que no se
requiere que el usuario final haga demasiadas acciones dentro de un corto
periodo de tiempo. Esto se debe a que la acción principal dentro de este
sistema es la de pedir la preparación de una receta, por lo que como solo hay
1 robot se tardará en preparar dicha receta un tiempo determinado donde el
usuario no hará ninguna otra petición.
T4 Procesamiento interno complejo: Se le ha asignado el valor de 2 porque
el sistema no necesita de un procesamiento complejo de datos ya que los
únicos cálculos que hará son el cálculo de posiciones y el cálculo de
estadísticas, ambos algoritmos muy sencillos.
T5 Reusabilidad: Se le ha asignado el valor de 4 ya que el sistema
proporciona una API para realizar las peticiones pertinentes, por lo que,
aunque principalmente se trabaje desde un entorno web se podrán desarrollar
otras aplicaciones que se comuniquen con esta API y generar las mismas
funcionalidades.
T6 Facilidad de instalación: Se le ha asignado el valor de 3 porque solo se
requiere de la instalación de ambos servidores, de una manera muy sencilla,
en algún equipo de la red.
T7 Facilidad de uso: Se le ha asignado el valor de 4 ya que se busca en todo
momento que el cliente vea de forma muy visual todas las opciones posibles,
interaccionando de la forma más sencilla posible como cualquier aplicación
de la vida cotidiana.
T8 Portabilidad: Se le ha asignado el valor de 3 ya que, aunque lo servidores
sean muy portables (están desarrollados sobre una plataforma disponible en
muchos sistemas operativos), se limita la portabilidad del sistema completo
por el hecho de tener el robot. El robot hace que sea necesario desplazarlo
de forma física, limitando así la portabilidad del sistema.
T9 Facilidad de cambio: Se le ha asignado el valor de 3 porque, al igual que
en el caso anterior, los servidores proporcionan gran flexibilidad ya que ambos
se comunican mediante una API desarrollada, facilitando en gran medida
nuevos cambios. El problema recae sobre el robot, ya que para realizar algún
cambio habría que modificar físicamente el robot y disponer de las piezas
necesarias para ello, además de realizar las modificaciones oportunas en el
servidor para las nuevas posiciones de los dispensadores, etc.
T10 Concurrencia: Se le ha asignado el valor de 1 porque, como ya se ha
comentado, aunque varios usuarios accedan a la vez a la aplicación esta solo

3 PLANIFICACIÓN TEMPORAL
3.1 TAREAS Y DIAGRAMA DE GANTT
Finalmente, una vez calculada la estimación del tiempo dependiendo de los casos de
uso, los actores y otros factores, se procede a calcular la planificación temporal del
proyecto.
Para ello establecerán una serie de fases siguiendo e modelo de Proceso Unificado,
donde cada fase tendrá una serie de iteraciones donde se desarrollará el proyecto de
forma incremental, implementando mejoras entre iteraciones.
Todo esto se hará a través de la herramienta Microsoft Project, que nos permite
establecer un calendario de trabajo estableciendo las horas que se va a trabajar en el
proyecto, además de establecer la duración de cada fase para establecer un resultado
total de días similar al estimado con el EZEstimate.

Ilustración 7. Calendario de trabajo y horario.

Una vez establecido el calendario de trabajo y el horario donde se trabajarán 8 horas
diarias se procede a establecer las distintas fases y sus iteraciones según el modelo del
Proceso Unificado.
Estas fases son:
•
•
•

•

Modelado de negocio: análisis, investigación y búsqueda de recursos y
relaciones con el proyecto.
Requisitos: se fijarán los objetivos, actores y requisitos del proyecto (se
pueden consultar en el Anexo II: Especificación de requisitos software.).
Análisis y diseño: Análisis de requisitos especificados durante la etapa
anterior junto al diseño de los distintos componentes del sistema,
determinando que componentes son necesarios y como funcionarán.
Implementación: Elaboración y programación del sistema usando lenguajes
de programación y las herramientas necesarias.
