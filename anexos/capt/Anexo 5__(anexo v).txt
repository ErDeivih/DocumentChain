1 INTRODUCCIÓN
Este documento está enfocado a proporcionar una explicación de la aplicación desde
el punto de vista del programador que quiera comprender el código.
El proyecto está estructurado en 3 apartados principales:
•

•

•

Servidor Cliente o Frontend: es el servidor que proporciona la web a la que
pueden acceder los usuarios. Este servidor se comunica mediante una API
REST con el Servidor API o Backend para obtener los datos necesarios,
realizar acciones en ellos o comunicarse con el robot.
Servidor API o Backend: servidor que ofrece una serie de servicios a través
de una API enfocada al Frontend (patrón BFF). Este servidor se encargará de
toda la parte lógica del proyecto, accediendo a la base de datos,
comunicándose con el robot o devolviendo resultados al Servidor Cliente o
Frontend.
Robot: incluye el firmware del robot y la API expuesta para la comunicación
con dicho robot. El firmware utilizado es “Marlin” mientras que para la
comunicación con el firmware mediante una API se ha decidido utilizar el
SSOO OctoPi para RaspberryPi, que incluye la API “Octoprint API” con la
posibilidad de mandar comandos GCODE de Marlin para el movimiento del
robot.

2 ESTRUCTURA COMPLETA DEL SISTEMA
En este apartado se explicarán más detalladamente cada componente del sistema.

2.1 SERVIDOR CLIENTE O FRONTEND
El código fuente del servidor Frontend desarrollado se encuentra dentro de la carpeta
“codigoFuente/client-fe”.
Este servidor ha sido desarrollado con Node.js y React, por lo que la estructura del
proyecto es la siguiente:
•

Carpeta src/: contiene todo el código encargado de generar las diferentes
páginas de la web. Contiene a su vez diferentes carpetas y archivos:
o index.js: archivo inicial que carga toda la página web llamando al
método render del DOM de react. Se encarga de cargar el
componente App.js encargado de cargar toda la página
o App.js
o routes.js: archivo donde se especifican las diferentes rutas accesibles
por el sistema.
o config.js: fichero con diferentes variables de comunicación
necesarias para el correcto funcionamiento del servidor y la correcta
conexión con el Backend.
o assets/: directorio encargado de guardar imágenes y temas que se
usan en la aplicación
o components/ y context/: guardan los componentes y el contexto de
la aplicación para la creación de nuevos componentes. Aquí se
almacenarán los componentes de la plantilla utilizada.
o layouts/: carpeta donde se almacenan de forma ordenada las
distintas páginas a las que accederán los usuarios. Estas páginas han
sido autodocumentadas utilizando la herramienta JSDoc, la cual crea
la carpeta “docs/” donde se almacena esta documentación.
o services/: contiene los controladores encargados de realizar las
peticiones a la API y que serán llamados desde las diferentes páginas
para realizar distintas acciones.

•
•

Carpeta docs/: contiene la documentación autogenerada por JSDoc
Carpeta public/: usada por React, contiene el HTML que usa React para
poder operar, y otros elementos como el favicon.

2.2. SERVIDOR API O BACKEND
El código fuente del servidor Backend desarrollado se encuentra dentro de la carpeta
“codigoFuente/server-be”.
Este servidor ha sido desarrollado con Node.js y Express, por lo que la estructura del
proyecto es la siguiente:
•

•

•

•
•
•
•

app.js y bin/www: ficheros de arranque de express donde se cargará toda la
lógica necesaria para la creación de la base de datos, preparación de routers,
etc para el correcto funcionamiento del servidor.
routes/: contiene los diferentes routers que ofrecen las rutas de la API a la
que se enviarán peticiones. Esta carpeta está autodocumentada usando
JSDoc.
services/: son los controladores que procesarán las peticiones recibidas por
la API y generarán una respuesta o una acción en el sistema. Esta carpeta
está autodocumentada usando JSDoc.
models/: incluye los diferentes modelos y relaciones que utilizará la biblioteca
Sequelize para trabajar con la base de datos.
middleware/: incluye algunos middleware encargados de realizar algunas
tareas de filtrado para algunas peticiones.
mailer/: guarda toda la lógica necesaria para el envío de emails y las plantillas
HTML usadas para los mismos.
docs/: contiene la documentación autogenerada por JSDoc
